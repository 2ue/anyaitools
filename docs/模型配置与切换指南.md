# 模型配置与切换指南

本文说明 Codex、Claude Code、Gemini CLI、OpenCode、OpenClaw、xAI Grok Build
六类模型工具的模型切换方式，并单独说明 MCP 这一外部工具配置层。文中区分：

- **原生方式**：直接使用工具官方支持的配置文件、命令或会话命令。
- **AnyAI Tools 方式**：使用 `aat` 管理服务商并写入工具配置。

这些工具的 `model` 字段含义并不相同。模型 ID、服务商、API 协议、variant、
推理强度、回退模型和图像模型应分别理解，不能把它们当成同一个开关。

## 模型工具一览

| 工具        | 原生模型入口                                                                                 | 主要配置文件                                                             | AnyAI Tools 当前状态                                                               |
| ----------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Codex       | `config.toml` 的 `model`；`codex --model <id>`；`review_model`                               | `~/.codex/config.toml`、`~/.codex/auth.json`                             | Core writer 和 Desktop 支持 `modelConfig`；CLI 可传模型 ID 和 effort               |
| Claude Code | `settings.json` 的 `model`；`claude --model <id>`；会话内 `/model`                           | `~/.claude/settings.json`                                                | Core writer 和 Desktop 支持模型与 effort；CLI 可传模型 ID 和 effort                |
| Gemini CLI  | `settings.json` 的 `model.name`；环境变量和 CLI 参数                                         | `~/.gemini/settings.json`、`~/.gemini/.env`                              | 同时写入 `model.name` 与兼容 `GEMINI_MODEL`；Desktop 支持 thinking budget          |
| OpenCode    | `opencode.json` 顶层 `model`；`opencode --model/-m`；variant                                 | `~/.config/opencode/opencode.json`                                       | Core writer 和 Desktop 支持 provider/model 与 variant；目录来自 Models.dev         |
| OpenClaw    | `models set/list/status`；`agents.defaults.model.primary`、`fallbacks`、`imageModel.primary` | `~/.openclaw/openclaw.json`、`~/.openclaw/agents/main/agent/models.json` | Core writer 和 Desktop 支持主模型、图像模型和 thinkingDefault；fallback 用原生 CLI |
| Grok Build  | `config.toml` 的 `models.default` 和 `[model.<alias>]`；命令行 `-m`                          | `$GROK_HOME/config.toml`（默认 `~/.grok/config.toml`）                   | 当前支持内置模型、自定义模型、API backend、backend search 和 provider 切换         |

## 先分清五种“模型相关设置”

1. **模型 ID**：真正发送请求的模型，例如 `gpt-5.5` 或 `claude-sonnet-...`。
2. **服务商/Provider**：模型从哪里调用。OpenCode 和 OpenClaw 通常要求写成
   `provider/model-id`。
3. **Variant 或推理强度**：同一个模型的运行档位，例如 OpenCode 的 `high`，
   Codex 的 `model_reasoning_effort = "xhigh"`。它们不是新模型。
4. **Fallback**：主模型不可用时才使用的备用模型。它不等于 variant，也不会改变
   主模型显示。
5. **图像模型/专用模型**：OpenClaw 的 `imageModel`、Claude 的 `opusplan` 等
   专用路由。它们可能与默认文本模型不同。

## AnyAI Tools 快速参数

CLI 的非交互添加/编辑支持手动模型和工具对应的推理参数；目录刷新与模型能力发现
在 Desktop 中完成：

```bash
aat cx add --name work --base-url https://api.example.com/v1 --api-key "$KEY" \
  --model gpt-5.5 --reasoning-effort high --switch
aat cc edit work --model claude-sonnet --reasoning-effort high
aat gm edit work --model gemini-model --thinking-budget 4096 --show-thinking
aat oc edit work --model openai/gpt-5.5 --model-variant high
aat openclaw edit work --model openai/gpt-5.5 --reasoning-effort high
aat gk edit work --model model-id --reasoning-effort high
```

`--reasoning-effort` 会保存为 effort，`--thinking-budget` 保存为 Gemini 的数字预算，
`--model-variant` 保存为 OpenCode variant；这些参数不会改变 MCP 配置。

## Codex

### 原生方式

在 `~/.codex/config.toml` 设置默认服务商和模型：

```toml
model_provider = "serverA"
model = "gpt-5.5"
review_model = "gpt-5.5"
model_reasoning_effort = "xhigh"

[model_providers.serverA]
name = "serverA"
base_url = "https://api.example.com/v1"
wire_api = "responses"
requires_openai_auth = true
```

临时切换时，命令行参数优先级最高：

```bash
codex --model gpt-5.5
```

`review_model` 是 `/review` 使用的独立模型；如果希望评审模型固定，必须单独
填写，不能只修改根级 `model`。`model_reasoning_effort` 和
`plan_mode_reasoning_effort` 只控制运行模式，不是模型 ID。

Codex 还支持用户级、项目级和 profile 配置。项目配置不能覆盖
`model_provider` 和 `model_providers`；需要长期切换时，应确认最终生效的配置层级。

### AnyAI Tools 方式

```bash
aat cx add
aat cx use <服务商ID>
aat cx current
```

核心层支持用 `provider.model` 写入根级 `model`，但当前 Desktop 的通用
ProviderForm 和 CLI 的 Codex 添加/编辑命令没有单独的模型输入项。也就是说：

- 只切换服务商时，模型通常沿用现有配置或模板默认值。
- 需要固定模型时，可先在 `~/.codex/config.toml` 手动设置 `model`，
  再用 AnyAI Tools 切换服务商。
- AnyAI Tools 不会自动把 `review_model`、推理强度和 Plan 模式一起改成同一个值。

验证：

```bash
aat cx current
grep -E '^(model_provider|model|review_model)' ~/.codex/config.toml
```

官方资料：<https://developers.openai.com/codex/config-reference/>

## Claude Code

### 原生方式

在 `~/.claude/settings.json` 设置启动时的初始模型：

```json
{
  "model": "sonnet",
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-ant-xxx",
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com"
  }
}
```

支持三种常用切换方式：

```bash
claude --model sonnet
claude --model claude-sonnet-4-20250514
```

进入会话后使用：

```text
/model
```

`sonnet`、`opus`、`haiku` 是官方动态别名；`opusplan` 是特殊模式，计划阶段使用
Opus，执行阶段使用 Sonnet。`availableModels` 可以限制 `/model` 的可选列表，
`enforceAvailableModels` 可以让默认模型也必须在允许列表中。

如果要让别名固定到某个具体版本，可以使用
`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL` 和
`ANTHROPIC_DEFAULT_HAIKU_MODEL` 等环境变量。

### AnyAI Tools 方式

```bash
aat cc add
aat cc use <服务商ID>
aat cc current
```

当前 writer 会更新认证字段，并在存在 `modelConfig.modelId` 时写入
`settings.model`；`reasoning.mode=effort` 会写入 `effortLevel`。Desktop 可刷新
目录、手动输入模型和设置 effort；CLI 非交互模式可传模型与强度。`aat cc use`
仍然同时执行服务商切换和 writer 写入，不等于 Claude 会话内的 `/model` 临时切换。

如果需要切换具体模型，建议：

1. 用 AnyAI Tools 切换服务商和认证。
2. 用 `claude --model` 或会话内 `/model` 选择模型。
3. 需要限制可选模型时，在 `settings.json` 配置 `availableModels`。

官方资料：<https://code.claude.com/docs/en/model-config>、
<https://code.claude.com/docs/en/settings>

## Gemini CLI

### 原生方式

当前官方配置结构使用嵌套的 `model.name`：

```json
{
  "model": {
    "name": "gemini-model-id"
  }
}
```

用户级配置位于 `~/.gemini/settings.json`，项目级配置位于项目目录的
`.gemini/settings.json`。环境变量和 CLI 参数也可能覆盖配置文件；具体参数名以
当前版本的 `gemini --help` 为准。

### AnyAI Tools 方式

```bash
aat gm add
aat gm use <服务商ID>
aat gm current
```

当前实现会维护：

```text
~/.gemini/settings.json
~/.gemini/.env
```

并把模型写入官方 `settings.json.model.name` 和兼容的 `.env` 变量
`GEMINI_MODEL`。`provider.model` 为普通字符串时会直接作为模型名；旧版 JSON
元数据仍可设置 `defaultModel` 和其他环境变量。Desktop 的 thinking budget 会写入
`modelConfigs.customAliases.anyaitools`。

`GEMINI_MODEL` 是兼容路径，不是官方结构的替代品；如果系统环境变量优先级更高，
仍需检查它是否覆盖 `.env` 和 `settings.json`。

验证：

```bash
aat gm current
grep '^GEMINI_MODEL=' ~/.gemini/.env
cat ~/.gemini/settings.json
```

官方资料：<https://google-gemini.github.io/gemini-cli/docs/get-started/configuration.html>

## OpenCode

### 原生方式

OpenCode 的默认模型必须是完整的 `provider/model-id`：

```json
{
  "model": "anthropic/claude-sonnet-4-20250514"
}
```

临时切换：

```bash
opencode --model anthropic/claude-sonnet-4-20250514
opencode -m anthropic/claude-sonnet-4-20250514
```

Provider 的模型定义位于：

```json
{
  "provider": {
    "openai": {
      "models": {
        "gpt-5.5": {
          "variants": {
            "low": {},
            "high": {}
          }
        }
      }
    }
  }
}
```

这里 `gpt-5.5` 是模型 ID，`low` 和 `high` 是同一模型的 variant。variant 可以
承载 reasoning effort、verbosity 等参数；不能把 variant 写进顶层 `model`。

模型选择优先级通常是命令行参数、配置文件、上次选择和内部默认值。遇到结果不符
时，应先检查命令行参数和当前会话状态。

### AnyAI Tools 方式

```bash
aat oc add
aat oc use <服务商ID>
aat oc current
```

当前 writer 会把 `modelConfig.modelId` 规范化为完整的 `provider/model-id`，并在
模型定义中维护选择的 model 和 variants。Desktop 可刷新 Models.dev/兼容目录并手动
输入；CLI 可传 `--model` 和 `--model-variant`。自定义 provider 仍需确认顶层
`model` 与 `provider.<id>.models` 定义一致。

官方资料：<https://opencode.ai/docs/models/>、
<https://opencode.ai/docs/config/>

## OpenClaw

### 原生方式

OpenClaw 使用完整的 `provider/model-id` 引用。核心配置通常包括：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "openai/gpt-5.5",
        "fallbacks": ["openai/gpt-4.1"]
      },
      "imageModel": {
        "primary": "openai/gpt-5.5"
      },
      "models": {
        "openai/gpt-4.1-mini": {
          "alias": "Fast"
        }
      }
    }
  }
}
```

模型池定义在 `models.providers.<provider>.models[]`，其中每个条目可以声明
`id`、`api`、`reasoning`、`input`、上下文窗口和 token 限制。`agents.defaults.models`
保存别名和模型级设置；它不会自动限制 `/model` 或 `--model` 的可选范围。
如果需要限制覆盖范围，使用 `agents.defaults.modelPolicy.allow`。

官方 CLI 可用于查看和设置：

```bash
openclaw models list
openclaw models status
openclaw models set openai/gpt-5.5
openclaw models set-image openai/gpt-5.5
openclaw models fallbacks add openai/gpt-4.1
openclaw models image-fallbacks add openai/gpt-4.1
openclaw models aliases add fast openai/gpt-4.1-mini
```

要注意：

- `primary` 是默认主模型。
- `fallbacks` 是主模型失败时的备用链。
- `imageModel.primary` 是图片请求的专用模型，和文本主模型独立。
- `image-fallbacks` 是图片模型的备用链。
- `input` 是能力声明，只能填写真实支持的输入模态；不要把它当成任意开关。
- `agents.defaults.models` 中的 alias 只是快捷名称，不等于 fallback。
- 创建独立 agent 时可以直接指定模型：

  ```bash
  openclaw agents add work --workspace ~/.openclaw/workspace-work \
    --model openai/gpt-5.5
  ```

  已有 agent 的覆盖应按 `agents.entries.<id>` 配置说明检查，而不是只看
  `agents.defaults`。

### AnyAI Tools 方式

```bash
aat openclaw add
aat openclaw use <服务商ID>
aat openclaw current
```

当前 writer 同时更新：

```text
~/.openclaw/openclaw.json
~/.openclaw/agents/main/agent/models.json
```

它会写入选择的模型（没有选择时回退 `gpt-5.5`），并把它设为
`agents.defaults.model.primary`；图像模型可通过 `modelConfig.parameters.imageModelId`
独立设置，同时保留其他未托管 provider。fallback、image-fallback、alias、
modelPolicy 和 agent 多模型路由仍应使用 OpenClaw 原生配置或 CLI。

官方资料：<https://docs.openclaw.ai/providers>、
<https://docs.openclaw.ai/gateway/configuration>、<https://docs.openclaw.ai/cli/models>

## xAI Grok Build

### 原生方式

用户级配置位于 `$GROK_HOME/config.toml`，未设置时为 `~/.grok/config.toml`。

官方内置模型只需要选择 catalog 模型：

```toml
[models]
default = "grok-build"
```

自定义端点使用 alias 和模型节点：

```toml
[models]
default = "custom"

[model.custom]
model = "model-id"
base_url = "https://gateway.example.com"
api_backend = "responses"
supports_backend_search = false
```

Grok Build 还支持通过命令行 `-m` 临时指定模型。除主模型外，Web 搜索、摘要和
图片描述等功能可能有各自的模型设置；它们不是同一个 `models.default` 字段。
企业 `requirements.toml`、环境变量和命令行参数也可能覆盖用户级配置。

### AnyAI Tools 方式

```bash
aat gk add --preset "xAI Grok Build" --switch
aat gk add --name gateway --base-url https://gateway.example.com \
  --api-key sk-example --model model-id --api-backend responses --switch
aat gk edit gateway --model newer-model
aat gk use gateway
grok inspect
```

这是当前 AnyAI Tools 对模型切换支持最完整的工具，支持：

- 官方内置模型和自定义模型。
- `chat_completions`、`responses`、`messages` 三种 API backend。
- backend search 能力开关。
- 保留其他模型、MCP、插件和未知配置字段。

官方资料：<https://docs.x.ai/build/overview>、
<https://docs.x.ai/build/settings>、
<https://docs.x.ai/build/settings/reference>

## MCP 配置层

MCP 只描述 server 的 command、args、env 和启用范围，不包含模型选择。
AnyAI Tools 会把 MCP 配置同步到 Claude Code 和 Gemini CLI；最终使用哪个模型，
仍由对应宿主工具的配置和命令决定。

## 推荐的验证顺序

1. 先看 AnyAI Tools 当前记录：`aat <tool> current`。
2. 再看工具官方配置文件中的模型字段。
3. 检查是否存在更高优先级的命令行参数、环境变量、项目配置或会话选择。
4. 重启工具或新建会话。
5. 使用工具自身的状态命令确认最终生效值，例如 `grok inspect`、
   `openclaw models status`。

## 当前实现边界

AnyAI Tools 当前统一管理服务商和“当前模型配置”，但不是所有工具的完整模型编排器：

- 六类模型工具的 Core writer 都读取 `modelConfig`，缺失时兼容旧 `model`。
- Desktop 已提供模型目录、手动输入和工具专属推理设置。
- CLI 的模型目录刷新仍以 Desktop 为主，命令行可使用手动模型和强度参数。
- OpenClaw 的 fallback、alias、modelPolicy 和 agent 路由仍由原生配置管理。
- MCP 不参与模型选择。

因此，新增工具时不应只新增一个字符串字段，而应先定义该工具的模型语义：
模型 ID、provider 引用格式、variant/推理参数、fallback、图像或其他专用模型，
再决定 AnyAI Tools 的结构化字段和 writer。
